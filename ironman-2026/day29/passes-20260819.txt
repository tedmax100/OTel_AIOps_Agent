---- what three passes inside one container measured ---------------------------

Nothing. Spread 0% on all five fixtures.

That is the result, not a failed experiment. It says the model, given a byte-
identical prompt against a container that never restarted, returns the same
verdict every time — which is what temperature 0 is supposed to mean, and it
rules the model out as the source of the swing this whole exercise started from.

The swings that were actually observed happened between *invocations*:

  order-service-auth-degradation, control arm, ab-intervention-20260819  3/3
  order-service-auth-degradation, control arm, ab-verification-20260819  0/3

Each of those booted its own container with `scenario_time = now`. The generator
is seeded (random.seed(42)) so the data is structurally identical between boots,
but every absolute timestamp shifts — and those timestamps are in the alert, in
the pinned clock, and in every window the agent computes. At temperature 0 a
changed prompt is a changed answer.

So the sampling unit is not the pass and not the seed. It is the invocation, and
what varies across it is the clock rather than the model. That reframes the
+-67pp: it is not noise to be averaged down with more samples, it is sensitivity
to input that should not matter. Averaging hides it; the fix is to measure it on
purpose by varying the scenario time and holding everything else.
